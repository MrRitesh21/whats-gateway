# Instagram comment → private reply (same WAFlow app)

This is a single-account, lightweight adaptation of the comment-to-DM flow in [Xeven777/openinstadm](https://github.com/Xeven777/openinstadm) (reviewed at commit `bd57e3a`, MIT-licensed), integrated into the existing WAFlow WhatsGateway app. It keeps the core comment parsing → keyword match → private reply → delivery log path, including webhook retries/deduplication, and is reimplemented against the host app's Prisma/Auth.js/UI. No upstream files are bundled.

It intentionally omits OpenInstaDM's separate BullMQ/Redis worker, OAuth/account management UI, multi-account workspaces, campaign builder, follow gate, tracked links, polling reconciliation, inbox, and public replies. The existing app's Postgres is the only additional persistence requirement; no extra service or runtime process is introduced.

## Behavior and safety

- Subscribe to the Instagram `comments` webhook field. Incoming payloads are accepted only when `X-Hub-Signature-256` validates against the raw request body and `META_APP_SECRET`.
- Events are scoped to `INSTAGRAM_ACCOUNT_ID`. Matching is case-insensitive and whole-word/phrase; comma-separated typo variants are supported.
- Each comment ID is claimed under a database unique constraint before calling Meta. Duplicate notifications cannot start a second send. Failed/ambiguous API outcomes are recorded and not automatically retried; an automatic retry could duplicate a DM if Meta accepted the first request but its response was lost.
- A matched comment gets one private reply containing `IG_DM_MESSAGE`, a newline, and `IG_DM_LINK`. Unmatched comments are also stored with `ignored` status.
- Dashboard/API access is restricted to signed-in SUPERADMIN users. The access token is read only from `INSTAGRAM_ACCESS_TOKEN` on the server.
- The app stores the last 50 events in the existing Postgres database. Instagram private replies must be sent within 7 days of a comment; comments on Instagram Live can only be replied to while the live broadcast is active.

## Environment variables

Set these in the existing app's `.env` locally and in the existing hosting service (never put token values in source control):

| Name | Purpose |
| --- | --- |
| `META_APP_SECRET` | Meta App Dashboard → App settings → Basic → App Secret |
| `META_WEBHOOK_VERIFY_TOKEN` | A long random string you choose; also enter the same string in the Meta webhook Verify Token field |
| `INSTAGRAM_ACCOUNT_ID` | Instagram professional account ID for the connected account |
| `INSTAGRAM_ACCESS_TOKEN` | Instagram User access token generated by Business Login for Instagram / Instagram Login |
| `IG_COMMENT_KEYWORDS` | Comma-separated trigger terms and typo variants, e.g. `price,prize,pricing` |
| `IG_DM_MESSAGE` | Private reply body; do not include the link here |
| `IG_DM_LINK` | The link appended on a new line |
| `META_GRAPH_API_VERSION` | Graph API version, currently defaulted to `v25.0` |

`.env.example` has empty/sample values. Replace keyword/message/link samples with your real choices; the previous request did not include actual keyword variants, final reply copy, or a destination link.

## Meta app setup

1. In [Meta for Developers](https://developers.facebook.com/), create/select the app used for the account. Add the Instagram product/use case and choose **Instagram API with Instagram Login** (Business Login for Instagram), not an unofficial automation provider.
2. In the app's Instagram setup, configure the OAuth redirect/callback URL required by Meta, then use Meta's official Instagram Login flow to authorize your Instagram **professional** account. Grant `instagram_business_basic` and `instagram_business_manage_comments`. The `INSTAGRAM_ACCESS_TOKEN` must be an Instagram User access token from this flow; keep it in the existing host's secret environment settings. Find the account ID from the authenticated account (`/me` via the Instagram API) and set `INSTAGRAM_ACCOUNT_ID`.
3. Ensure the Instagram account is professional and public. Use app roles/testers and Standard Access for development with accounts you own/manage. If the app serves other businesses, request Advanced Access and complete Meta's applicable review/business verification requirements.
4. Deploy the updated existing app over HTTPS and set all environment variables above. Apply the new model to its existing Postgres database with `npx prisma db push` (or the repository's `npm run db:push`), then restart/redeploy the same service.
5. In Meta App Dashboard → **Webhooks**, select the Instagram object and add callback URL `https://YOUR_EXISTING_HOST/api/webhooks/instagram`. Enter the exact `META_WEBHOOK_VERIFY_TOKEN` value. Meta makes a GET challenge request; the app validates it and echoes the challenge.
6. Subscribe the `comments` field. The app must also be subscribed to the Instagram professional account. Using the authorized Instagram User access token, call the documented `/{ig-user-id}/subscribed_apps` endpoint with `subscribed_fields=comments` (Meta's API version and access-token rules apply). Confirm the subscription succeeds.
7. For delivery outside app-role/test accounts, set the Meta app Live and request the required access level. Test with a real comment containing one configured keyword; check `/dashboard/instagram-comments` for a `DM sent` status. Check failed events and app logs if the API refuses the private reply.

## Existing app deployment

This feature is deployed as part of the current WhatsGateway project: commit/ship these source changes through the existing project pipeline, set the seven Instagram environment variables in the current hosting service, run `npm run db:push` once against its configured `DATABASE_URL`, then rebuild/redeploy. Do not create a separate Next.js service. The webhook callback always uses the existing host's domain.
